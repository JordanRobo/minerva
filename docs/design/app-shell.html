Minerva · App shell

The frame every signed-in screen lives inside.

One shell for staff, administrators and read-only viewers — sidebar, page header, banner slot and content area. The controls under each frame switch variants in place; page content is placeholder only, so the shell can be judged on its own.

Desktop shell

One frame covers all three desktop variants: Staff (no Admin group, primary action present), Administrator (Admin group appears), and Read-only (primary action absent). The banner, collapsed sidebar and dark mode are toggles. Content states — loading, empty, error, 403 — replace the content area only; the frame never moves.

New tokens for the design system

Everything else — colours, type, radius, the 4px spacing grid, 1px borders — is the existing Minerva system. The shell adds only these layout tokens, as CSS custom properties. No new colour tokens: light mode uses the registered palette; dark mode uses the posture values (canvas #171A28, cards #1E2233, text #F3ECE1, ember accent).

TokenValuePurpose
--shell-sidebar-w264pxExpanded sidebar, desktop
--shell-sidebar-w-min72pxCollapsed sidebar, icons only

--shell-pad32px · 20px mobileContent area padding
--shell-topbar-h56pxMobile top bar height
--shell-tabbar-h64pxMobile tab bar height, plus env(safe-area-inset-bottom)
--touch-min44pxMinimum tap target, mobile

Focus ring: 2px solid accent, 2px offset — accent is terracotta on light, ember on dark. Primary button labels sit on the accent at 18px minimum, per posture.

Building it in SvelteKit

(app)/+layout.svelte

Shell route group

One layout renders the frame: skip link first in DOM, then aside with two labelled navs, then the main column (banner slot, header, content). Pre-sign-in screens sit outside the group and use BareAuthLayout.

layout
data.user.role

Role gating

Same mapping as the data-role attribute here: {#if role === 'admin'} renders AdminGroup; {#if role !== 'readonly'} renders the primary action. Role comes from the server session, never the client.

roles
+page.ts → error(403)

403 flow

Permission checks throw error(403); +error.svelte renders AccessDenied inside the shell, so the frame stays put.

error
tokens.css

Tokens

Append the seven shell tokens from above to the design system's tokens.css; import once in app.html. Dark mode: prefers-color-scheme flips the same shell variables the .dark class demonstrates here.

tokens
a11y baseline

Accessibility

Skip link focuses main[tabindex="-1"]; visible :focus-visible ring on everything; landmarks: nav ×2 (aria-label), header, main. 44px targets on mobile. Contrast: ink on cream 14.7:1, slate on cream 5.8:1, white on terracotta 4.6:1, ink on ember 5.8:1 (dark).

baseline
localStorage

State restoration

Remember the last-visited destination the same way this prototype persists its demo controls — one key, a couple of fields. No session storage needed.
