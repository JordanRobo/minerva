# UI → Bits UI migration audit (roadmap 6.6)

Prepared 2026-10-15 on `feature/73-bits-ui-migration` (cut from main at tag `pre-bits-ui`, commit `8939724`).
Scope: every Svelte component and route under `apps/web/src`.

**Status (updated 2026-10-15, step 3):** the three native `<dialog>`s are migrated to **Bits UI Dialog** (bits-ui 2.19.5) — ConfirmDialog, LinkDialog and UserSheet now keep their public props with the open state mirrored into a local `bitsOpen` via a function binding (`bind:open={getOpen, setOpen}`); ConfirmDialog's refuses-to-close-while-busy rule lives in that setter (every close attempt — Escape, outside click, Cancel — funnels through it). Shared overlay/card chrome moved to `src/lib/styles/dialogs.css` (imported once from the root layout), styled with `--minerva-*` tokens; portaled content is brought back into component scope with `child` snippets. The Sidebar user menu is migrated to **Bits UI Popover** (step 3a) — a disclosure, deliberately not DropdownMenu — and the four `title=` tooltips to **Bits UI Tooltip** (step 3b), with one `Tooltip.Provider` in the `(app)` layout; the tooltip bubble and the disabled-button trigger wrapper joined `dialogs.css`. One trap found in step 3b: a delegated element's `{...props}` spread must come *before* an explicit `onclick`, or the primitive's own click handler clobbers it (the collapse toggle silently stopped working until reordered). Step 3c closed out the first pass of the audit: the SSO inline-edit row now reuses `Input.svelte` — an optional `ref` binding added to the component forwards to the inner element, so focus still moves in when Edit is pressed — and its duplicated `.group-input` styles are gone.

**Status (updated 2026-10-16, step 4):** owner decision supersedes D18's "layout and display components stay custom" — Bits UI is now used for **every component that has a Bits UI primitive**; custom components are kept only where none exists. The keep-custom calls for Button, Field's label, PasswordInput's toggle, the SSO `<details>` and the four native `<select>`s are re-opened below; new rows added for Separator (the login "or" divider, the user-menu rule, the two mobile-sheet rules) and for Avatar, Progress and ScrollArea (re-checked — no migration). Step 4 migrates Button (4a), Field's label (4b), PasswordInput's toggle (4c), the `<details>` (4d) and the Separators (4e); the `<select>`s follow as a separate step.

**Status (updated 2026-10-19, step 5):** the four native `<select>`s are migrated to **Bits UI Select** — one shared wrapper `ui/Select.svelte` (a trigger button plus a portaled listbox; the primitive owns open state, keyboard handling — arrows / typeahead / Enter+Space / Escape — ARIA and focus, with the trigger keeping focus the whole time per the descendant pattern). Pages keep their own state: People binds each row's draft into/out of a `draftRoles` object (keyed by user id) with a getter/setter function binding, Invitations and SSO bind their form state directly. The manual `onchange` value re-validation goes with the native handler (the primitive only ever emits one of the option values); `<label for>` pairing still works because `id` flows through to the trigger button.

Two Svelte 5 reactivity traps surfaced in acceptance, both fixed at the root: (1) `$state` proxies plain objects and arrays but **not** Maps — People's original `draftRoles = $state(new Map())` ran the setter but fired no signal, so the Apply button never appeared; that was a latent bug in the pre-migration native-select page too (verified live against the old code: changing the role never surfaced Apply), not a migration regression. `draftRoles` is now a plain `$state({})` object keyed by user id. (2) A keyed each block keeps its original item object while the key is unchanged, so replacing array elements (`users.map(...)`, `rules.map(...)`) left the row's closures reading stale objects after a role change or rule save; People's `replaceUser` and SSO's `saveRule` now mutate the row's object in place (SSO reassigns the sorted array only when the order actually changed, to reorder without remounting).

Acceptance is green — headless Chrome over CDP against the running compose stack, 1280px and 480px, light and dark, mouse and keyboard-only: gallery (closed / open via `bind:open` / disabled / long-label truncation; listbox portaled to `<body>` at z-index 50 above the popover's 40, options ≥44px); full keyboard flow on a trigger (Enter/Space open, typeahead, arrows, Enter/Space choose, Escape closes with focus on the trigger, outside-click close drops focus exactly as native does); Invitations creates an invite with the chosen role and the show-once link; accept-invite signs the new user straight in; People's draft → Apply → confirm → row updates (plus a keyboard round trip where Apply reappears), own-row disabled + helper, SSO-managed rows read-only with badge and no picker; SSO add-rule with first-rule confirm, inline edit (focus into the input, role change, save) and last-rule confirm back to the empty state; at 480px the listbox opens over table rows and stacked cards with no viewport clipping and no scroll jump; dark mode repaints trigger and listbox from tokens. `bun run check`: 0 errors 0 warnings; `bun run build` passes.

**Status (updated 2026-10-19, close-out):** 6.6 is complete — every component that has a Bits UI primitive now uses one. The final interactive-element audit below accounts for every native interactive element in the app (a fresh grep sweep found nothing missed), and the full M6 regression was re-run green for close-out.

## Bits UI version

**bits-ui 2.19.5** (latest on npm as of 2026-10-15). Peer dependency `svelte ^5.33.0`; the app is on `svelte ^5.56.1` with SvelteKit 2 — **Svelte 5 support confirmed**. The other peer, `@internationalized/date ^3.8.1`, is only required by the date components (Calendar / DatePicker / …), which Minerva does not use — not needed at install.

Rule applied (D18 as amended 2026-10-16): use a Bits UI primitive for **every component that has one**, styled with the `--minerva-*` tokens; custom components are kept only where no primitive exists. Public component props are preserved so pages do not change.

## Cross-cutting notes for the implementation steps

1. **FormAlert is load-bearing**: `role="alert"` + `tabindex="-1"` — three auth pages focus `form [role="alert"]` after a failed submit. Keep both attributes and the focusability intact.
2. **Dev gallery in lockstep**: it demos both dialogs; its static title ids (`confirm-dialog-title`, `link-dialog-title`) and one-at-a-time mount constraint disappear with Bits UI's auto-generated ids — resolved in step 2, which also added the busy and error confirm demos.
3. **Tooltips need a provider** — resolved (step 3b): one `Tooltip.Provider` wraps the whole `(app)` shell layout, so every tooltip in signed-in routes shares it; it coordinates at most one visible tooltip and supplies the hover delay.
4. **Portals + scoped styles**: Dialog content renders in a portal; Popover and Tooltip content render inline (no `Portal` part is used), positioned by floating-ui. Either way Svelte scoped `<style>` won't reach foreign markup — use the `child` snippet to render own elements (spreading `{...props}`) or target data attributes with `:global(...)`. Minerva uses `child` everywhere; the shared chrome (overlay, card, bubble, `.disabled-tip`) lives in `dialogs.css`.
5. **Styling stays token-based**: all new primitive markup is styled with the existing `--minerva-*` tokens, matching D18 and the design system in `docs/design/`.
