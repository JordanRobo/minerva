# UI → Bits UI migration audit (roadmap 6.6)

Prepared 2026-10-15 on `feature/73-bits-ui-migration` (cut from main at tag `pre-bits-ui`, commit `8939724`).
Scope: every Svelte component and route under `apps/web/src`.

**Status (updated 2026-10-15, step 3):** the three native `<dialog>`s are migrated to **Bits UI Dialog** (bits-ui 2.19.5) — ConfirmDialog, LinkDialog and UserSheet now keep their public props with the open state mirrored into a local `bitsOpen` via a function binding (`bind:open={getOpen, setOpen}`); ConfirmDialog's refuses-to-close-while-busy rule lives in that setter (every close attempt — Escape, outside click, Cancel — funnels through it). Shared overlay/card chrome moved to `src/lib/styles/dialogs.css` (imported once from the root layout), styled with `--minerva-*` tokens; portaled content is brought back into component scope with `child` snippets. The Sidebar user menu is migrated to **Bits UI Popover** (step 3a) — a disclosure, deliberately not DropdownMenu — and the four `title=` tooltips to **Bits UI Tooltip** (step 3b), with one `Tooltip.Provider` in the `(app)` layout; the tooltip bubble and the disabled-button trigger wrapper joined `dialogs.css`. One trap found in step 3b: a delegated element's `{...props}` spread must come *before* an explicit `onclick`, or the primitive's own click handler clobbers it (the collapse toggle silently stopped working until reordered). Remaining: the SSO inline-edit row reuses `Input.svelte` (step 3c).

## Bits UI version

**bits-ui 2.19.5** (latest on npm as of 2026-10-15). Peer dependency `svelte ^5.33.0`; the app is on `svelte ^5.56.1` with SvelteKit 2 — **Svelte 5 support confirmed**. The other peer, `@internationalized/date ^3.8.1`, is only required by the date components (Calendar / DatePicker / …), which Minerva does not use — not needed at install.

Rule applied (D18 + task constraint): recommend a Bits UI replacement **only where it removes custom behaviour code**. Layout and display components stay custom; public component props are preserved so pages do not change.

## Cross-cutting notes for the implementation steps

1. **FormAlert is load-bearing**: `role="alert"` + `tabindex="-1"` — three auth pages focus `form [role="alert"]` after a failed submit. Keep both attributes and the focusability intact.
2. **Dev gallery in lockstep**: it demos both dialogs; its static title ids (`confirm-dialog-title`, `link-dialog-title`) and one-at-a-time mount constraint disappear with Bits UI's auto-generated ids — resolved in step 2, which also added the busy and error confirm demos.
3. **Tooltips need a provider** — resolved (step 3b): one `Tooltip.Provider` wraps the whole `(app)` shell layout, so every tooltip in signed-in routes shares it; it coordinates at most one visible tooltip and supplies the hover delay.
4. **Portals + scoped styles**: Dialog content renders in a portal; Popover and Tooltip content render inline (no `Portal` part is used), positioned by floating-ui. Either way Svelte scoped `<style>` won't reach foreign markup — use the `child` snippet to render own elements (spreading `{...props}`) or target data attributes with `:global(...)`. Minerva uses `child` everywhere; the shared chrome (overlay, card, bubble, `.disabled-tip`) lives in `dialogs.css`.
5. **Styling stays token-based**: all new primitive markup is styled with the existing `--minerva-*` tokens, matching D18 and the design system in `docs/design/`.

## Summary — what actually migrates

- 3 native `<dialog>`s → **Bits UI Dialog** (ConfirmDialog, LinkDialog, UserSheet) — **done (step 2)**
- 1 hand-rolled disclosure (~40 lines of manual keyboard/outside-click/focus code) → **Bits UI Popover** (Sidebar user menu) — **done (step 3a)**
- 4 `title=` tooltips → **Bits UI Tooltip** (2 in the shell; 2 on disabled buttons that never displayed at all) — **done (step 3b)**

Everything else stays custom: Button, Input/PasswordInput/Field/FormAlert, PageHeader/Banner/Skeletons, the states family, all shell layout and navigation, Icon, all four native `<select>`s, and the one native `<details>`.
